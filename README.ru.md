# alertboard

[English](README.md) · **Русский**

Веб-страница с активными алертами Alertmanager: группировка, шкала времени начала, поиск, сохранённые виды, ссылки в Prometheus и на создание silence. Только чтение.

## Сборка и запуск

Только чтение: GUI ничего не меняет в Alertmanager, silence создаётся в его родном интерфейсе по готовой ссылке.

Нужен Node 22+. Бэкенд — NestJS (`server/`), фронтенд — Vue 3 (`web/`), бэкенд отдаёт собранный `web/dist`.

```bash
cp config.example.yaml config.yaml   # поправить адреса и категории
cp .env.example .env                 # логин и пароль Alertmanager
make build
node server/dist/main.js --config config.yaml
# http://127.0.0.1:8080
```

Флаги: `--config` (по умолчанию `config.yaml`), `--listen` (перекрывает `LISTEN` и `listen` из конфига), `--env` (по умолчанию `.env` в текущем каталоге; если файла нет, он пропускается).

Переменные окружения: `AM_USER`, `AM_PASSWORD`, `LISTEN`, `AUTH_USER`, `AUTH_PASSWORD`. Их можно задать в `.env` или в окружении; уже заданные в окружении важнее файла. Логин и пароль Alertmanager в браузер не отдаются.

Разработка: `make dev` поднимает бэкенд (перезапускается при правках `server/src`) и Vite с hot reload. Vite проксирует `/api` на адрес бэкенда: `LISTEN`, затем `listen` из конфига. Другой конфиг или `.env`: `make dev CONFIG=other.yaml ENV_FILE=.env.local`, то же для `make run`.

Тесты: `make test`.

## Docker

```bash
cp config.example.yaml config.yaml
docker build -t alertboard .
docker run -d -p 8080:8080 \
  -e AM_USER=... -e AM_PASSWORD=... \
  -v "$PWD/config.yaml:/etc/alertboard/config.yaml:ro" \
  alertboard
```

Или `docker compose up -d` с `compose.yaml` из репозитория: логин и пароль берутся из `.env` рядом с ним. `docker run --env-file` передаёт значения буквально, вместе с кавычками, поэтому в файле для него значения в кавычки не берите. В образе `LISTEN=0.0.0.0:8080`, поэтому `listen` из конфига в контейнере не используется. Готовые образы для `linux/amd64` и `linux/arm64` публикуются в `ghcr.io/wendor/alertboard` при пуше тега `v*`.

## Авторизация

Если заданы `AUTH_USER` и `AUTH_PASSWORD`, весь интерфейс и API закрываются HTTP basic auth. Задавать нужно обе переменные, иначе сервер не стартует. Без них страница открыта, поэтому держите её на localhost или в доверенной сети (`compose.yaml` из репозитория публикует порт только на `127.0.0.1`). Basic auth передаёт пароль в каждом запросе, так что за пределами доверенной сети отдавайте страницу по HTTPS, например через reverse proxy.

## Конфиг

Описание полей есть в `config.example.yaml`. Основное:

- `alertmanager.url` — откуда бэкенд читает `/api/v2/alerts`; `public_url` — адрес для ссылок на silence в браузере.
- `prometheus.url` / `name` — основной Prometheus для ссылок (по умолчанию ссылка называется `prom`), `prometheus.extra` — дополнительные, выводятся рядом. На каждый из них переписывается хост `generatorURL` алерта с сохранением пути и запроса. Это нужно, если у Prometheus не задан `--web.external-url` и в алертах стоит внутренний адрес (например, id контейнера). Без `prometheus.url` ссылка остаётся как в алерте.
- `grafana` — ссылки на Grafana Explore с выражением алерта (берётся из `generatorURL`), интервал от часа до начала алерта до сейчас, но не меньше 6 и не больше 24 последних часов. Нужны `url` и `datasource` — uid Prometheus-datasource (виден в адресе Explore после выбора datasource), `org_id` по умолчанию 1. Дашборд не нужен.
- `problems` — регулярки по `alertname` (якорятся целиком), первая совпавшая даёт название проблемы. Без совпадения проблема называется по `alertname`.
- `ui.groups` — порядок и названия значений `ui.group_label` (по умолчанию `severity`). Алерты без этого лейбла попадают в «без группы».
- `ui.stale_after` — после какого возраста алерт считается давним и уходит в свёрнутую секцию; `ui.fresh_within` — до какого возраста подсвечивается.
- `ui.host_labels` — из каких лейблов брать «хост» алерта, первый непустой (по умолчанию `[instance]`).
- `ui.group_by_labels` — дополнительные варианты группировки по произвольным лейблам: `{label, title}`.
- `ui.search_skip_labels` — лейблы, по которым не ищет свободный текст: полезно для служебных лейблов с длинными списками значений, которые совпадают почти с любым словом. Фильтр `label=…` по ним работает.
- `ui.links` — дополнительные ссылки у каждого алерта, `{{label}}` подставляет значение лейбла.
- `ui.views` — виды по умолчанию.

## Языки

Интерфейс на русском и английском. По умолчанию язык берётся из браузера, переключатель `RU`/`EN` в шапке, выбор запоминается в браузере.

Названия из конфига (`problems[].title`, `ui.groups[].title`, `ui.group_by_labels[].title`, `ui.links[].name`, `ui.views[].name`) можно задать строкой или словарём `{ru: …, en: …}`. Если перевода на текущий язык нет, берётся английский, затем любой. Первый перевод в словаре — постоянный ключ: по нему запоминаются скрытые проблемы и сохранённые виды, поэтому менять его не стоит.

## Поиск

Слова через пробел, все должны совпасть:

- `текст` — подстрока в `alertname`, названии проблемы, аннотациях, значениях лейблов, кроме `ui.search_skip_labels` (без учёта регистра);
- `label=value`, `label!=value`, `label=~regex`, `label!~regex` — как в PromQL, регулярка целиком;
- кавычки для пробелов: `mountpoint="mount point /"`.

## Виды

Вид — это поиск, группировка, скрытые группы и проблемы, показ silenced, порог давности, масштаб шкалы. Изменения отмечаются точкой у вкладки, «сохранить» записывает их в вид. Виды хранятся в `localStorage` браузера: пока там что-то есть, виды из конфига не применяются. Текущее состояние, включая выделенный интервал шкалы, лежит в адресе страницы, поэтому им можно поделиться ссылкой.
